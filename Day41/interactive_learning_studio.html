Foundations of Selection

Beginner · Understanding indexing
▼
📘 Explanation

A Pandas DataFrame is a 2D labeled table — rows have an index, columns have names. Because both axes are labeled, Pandas gives you three distinct ways to select data, and mixing them up is the #1 source of bugs for beginners.

Analogy: Think of a DataFrame like an Excel sheet where every row has a name-tag (index) and every column has a header. .loc asks "give me the row/column by their name-tag/header", while .iloc asks "give me by their position number, like a seat number, regardless of the label".
🧪 Core Selection Methods
# Selecting a single column -> returns a Series df['age'] # Selecting multiple columns -> returns a DataFrame df[['name', 'city']] # .loc -> label-based selection (row label, column label) df.loc[0, 'name'] # single value df.loc[0:2, ['name','age']]# slice + column list # .iloc -> position-based selection (integer index only) df.iloc[0, 1] # row 0, column 1 df.iloc[0:2, 0:2] # first 2 rows, first 2 cols
MethodSelects BySlice End Included?Use When
df[]Column name(s)N/AQuick column access
.loc[]Labels (index/columns)Yes (inclusive)You know the label names
.iloc[]Integer positionNo (exclusive, like Python)You know the position, not the label
⚠️ Common Misconceptions
Myth: "df.loc[0:2] and df.iloc[0:2] return the same rows."
Reality: .loc[0:2] includes row label 2 (3 rows), while .iloc[0:2] excludes position 2 (2 rows) — because .loc is label-inclusive and .iloc behaves like normal Python slicing.
Myth: "df['col'] and df.col always work the same."
Reality: Dot-notation breaks if the column name has spaces, matches a DataFrame method name, or is stored as a variable — so df['col'] is the safer, recommended habit.
💪 Practical Exercise
Given a DataFrame df with columns name, age, city, write the code to select the age and city columns for rows at index positions 1 through 3 (inclusive) using .iloc.
df.iloc[1:4, [1, 2]] # iloc end is exclusive, so 1:4 covers positions 1,2,3
✅ Key Takeaways
  • df['col'] for quick single/multi column access
  • .loc = label-based, slice end inclusive
  • .iloc = position-based, slice end exclusive
  • Always prefer bracket notation over dot notation for safety

Filtering with Boolean Masks

Beginner–Intermediate · Conditional logic
▼
📘 Explanation

Filtering means keeping only the rows that satisfy a condition. Pandas does this via boolean masks — an array of True/False values, one per row, that you use to index the DataFrame.

Analogy: Imagine every row raises a hand (True) or keeps it down (False) when asked "do you match the condition?". df[mask] only keeps the rows with their hand up.
🧪 Building Filters
# Single condition df[df['age'] > 28] # Multiple conditions -> use & / | with parentheses (NOT and/or) df[(df['age'] > 25) & (df['city'] == 'Delhi')] # Negation df[~(df['city'] == 'Pune')] # Membership test df[df['city'].isin(['Delhi', 'Pune'])] # String conditions df[df['name'].str.startswith('A')]
OperatorMeaningWorks on Series?
and / orPython boolean logic❌ No — raises error
& / |Element-wise AND/OR✅ Yes — required for masks
~Element-wise NOT✅ Yes
⚠️ Common Misconceptions
Myth: "I can use `and`/`or` to combine conditions like in normal Python."
Reality: Pandas conditions produce arrays of booleans, and Python's `and`/`or` only work on single booleans — you must use `&`, `|`, and wrap each condition in parentheses.
Myth: "Forgetting parentheses is just a style choice."
Reality: df['age'] > 25 & df['city']=='Delhi' throws an error or gives wrong results because & has higher precedence than > in Python — parentheses are mandatory.
💪 Practical Exercise
Write a filter that keeps rows where age is between 25 and 35 (inclusive) AND city is NOT 'Pune'.
df[(df['age'] >= 25) & (df['age'] <= 35) & (df['city'] != 'Pune')]
✅ Key Takeaways
  • Filtering = indexing a DataFrame with a boolean mask
  • Use &, |, ~ — never and/or
  • Always wrap each condition in parentheses
  • .isin() is cleaner than chained OR conditions

Cleaning Missing & Messy Data

Intermediate · Data quality
▼
📘 Explanation

Real datasets are messy: missing values (NaN), duplicate rows, and wrong data types. Cleaning means detecting these issues systematically and deciding whether to fill, drop, or convert.

Analogy: Missing values are like blank cells in a paper form — you can throw the whole form away (drop), guess a reasonable answer (fill), or leave a note explaining why it's blank. Pandas gives you a tool for each.
🧪 Detecting & Handling Missing Data
# Detect missing values df.isna().sum() # count of NaN per column df.isna().any(axis=1) # rows with at least one NaN # Drop rows/columns with missing data df.dropna() # drop any row with a NaN df.dropna(subset=['age']) # drop only if 'age' is NaN df.dropna(thresh=3) # keep rows with >=3 non-NaN values # Fill missing data df['age'].fillna(df['age'].mean(), inplace=True) df['city'].fillna('Unknown', inplace=True)
🧪 Duplicates & Data Types
# Duplicates df.duplicated().sum() # count duplicate rows df.drop_duplicates(inplace=True) # Fixing data types df['age'] = df['age'].astype(int) df['joined'] = pd.to_datetime(df['joined']) df.dtypes # inspect current types
MethodPurposeRisk
dropna()Remove missing rows/colsCan lose valid data
fillna()Replace missing with a valueCan distort statistics if overused
drop_duplicates()Remove repeated rowsMay remove legitimately identical rows
astype()Convert column typeFails if values aren't convertible
⚠️ Common Misconceptions
Myth: "Always drop rows with missing values — it's the safest option."
Reality: Dropping can throw away large portions of usable data. In practice, analysts often use fillna() with mean/median/mode or domain-specific defaults instead.
Myth: "NaN == NaN is True, so I can filter missing values with df[df['col']==NaN]."
Reality: NaN is never equal to itself in Pandas/NumPy — you must use df['col'].isna() to detect it.
💪 Practical Exercise
Write code that: (1) fills missing 'age' values with the column median, and (2) drops any remaining duplicate rows.
df['age'].fillna(df['age'].median(), inplace=True) df.drop_duplicates(inplace=True)
✅ Key Takeaways
  • Use isna() to detect missing values — never compare to NaN directly
  • Choose drop vs fill based on how much data you can afford to lose
  • drop_duplicates() keeps the first occurrence by default
  • Always verify types with .dtypes after cleaning

Combining Skills: Real Analysis Workflows

Advanced · Mastery & chaining
▼
📘 Explanation

Real analyst work chains selection, filtering, and cleaning together — often in one readable pipeline using method chaining. Mastery means writing this fluently and knowing when to use .query() versus boolean masks, and how .loc enables safe in-place edits.

Analogy: Think of a data pipeline like an assembly line: raw data enters, each station (clean → filter → select) transforms it a bit, and a polished result exits at the end — each step depends on a clean output from the one before it.
🧪 Chaining It All Together
# Full pipeline: clean, then filter, then select result = ( df.dropna(subset=['age']) .drop_duplicates() .loc[lambda d: (d['age'] >= 25) & (d['city'] != 'Pune'), ['name', 'age', 'city']] ) # .query() -> readable alternative to boolean masks df.query("age >= 25 and city != 'Pune'") # Safe conditional update using .loc (avoids SettingWithCopyWarning) df.loc[df['age'] < 18, 'category'] = 'Minor'
Pro tip: SettingWithCopyWarning appears when you edit a filtered slice without .loc. Always use df.loc[condition, 'col'] = value for conditional edits — never df[condition]['col'] = value.
⚠️ Common Misconceptions
Myth: "df[condition]['col'] = value is a safe way to edit filtered data."
Reality: This creates a copy in an ambiguous way and triggers SettingWithCopyWarning — the edit may silently fail. Use df.loc[condition, 'col'] = value instead.
Myth: ".query() is just a slower version of boolean masks with no benefit."
Reality: .query() is often more readable for complex multi-condition filters and can be faster on large DataFrames because it uses optimized expression evaluation.
💪 Practical Exercise
Write a single chained pipeline that: drops duplicate rows, fills missing 'age' with the mean, then selects 'name' and 'age' for people older than 30.
result = ( df.drop_duplicates() .assign(age=lambda d: d['age'].fillna(d['age'].mean())) .loc[lambda d: d['age'] > 30, ['name', 'age']] )
✅ Key Takeaways
  • Chain .dropna() → .drop_duplicates() → .loc[filter, cols] for clean pipelines
  • Use .loc[condition, 'col'] = value for safe conditional edits
  • .query() is a readable alternative for complex filters
  • Always clean before filtering — dirty data skews conditions

📝 Module 4 Quiz

1. What's the safe way to conditionally update a column?

df[condition]['col'] = value
df.loc[condition, 'col'] = value
df.col[condition] = value
df.update(condition, value)
Correct: df.loc[condition, 'col'] = value — avoids SettingWithCopyWarning and guarantees the edit applies to the original DataFrame.

2. Which correctly rewrites df[(df['age']>=25)&(df['city']!='Pune')] using .query()?

df.query(age>=25, city!='Pune')
df.query['age>=25 and city!=Pune']
df.query("age >= 25 and city != 'Pune'")
df.filter("age>=25 & city!='Pune'")
Correct: df.query("age >= 25 and city != 'Pune'") — .query() takes a single readable string expression.

3. In a clean → filter → select pipeline, why clean first?

Dirty data (NaN, duplicates) can skew or break filter conditions
Pandas requires cleaning to run first, otherwise it errors
Cleaning is always faster than filtering
There's no real reason, order doesn't matter
Correct: Dirty data can skew or break filter conditions — e.g. NaN comparisons or duplicate rows distorting counts.

4. What triggers a SettingWithCopyWarning?

Using .loc for selection
Using .query() to filter
Reading a CSV file
Editing a filtered slice without .loc
Correct: Editing a filtered slice without .loc — Pandas can't guarantee whether you're editing a view or a copy.
🏁 Final Challenge

Put It All Together

You're given a messy employee DataFrame df with columns name, age, department, salary, joined. It has missing ages, duplicate rows, and salary stored as strings like "45000". Write a pipeline that: removes duplicates, fills missing age with the median, converts salary to integer, then returns name and salary for employees in the 'Sales' department earning above 50000, sorted by salary descending.

result = ( df.drop_duplicates() .assign( age=lambda d: d['age'].fillna(d['age'].median()), salary=lambda d: d['salary'].astype(int) ) .loc[lambda d: (d['department'] == 'Sales') & (d['salary'] > 50000), ['name', 'salary']] .sort_values('salary', ascending=False) )
