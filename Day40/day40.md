# 📅 Day 40 / 60 — ABTalks Claude AI Mastery Challenge

**Build:** Deskside — AI Assistant Builder → Concept Tutor for Data Analyst / Data Science interview prep
**Category:** Meta / EdTech — building an assistant *builder* process, applied to an education use case
**Time invested:** ~1 session
**Status:** ✅ Complete, working end-to-end

## What today was about

Rather than building a single app from a fixed spec, today I practiced acting as an **AI product team of
one** — product manager, prompt engineer, and frontend developer — using a repeatable process:

`Interview the requirements → Design the system prompt → Build the interface → Document the "why"`

I applied that process to a real need from my own job search: a fast way to drill CS / Data Analyst
interview concepts (SQL, stats, DSA) into structured, testable study cards.

## Key deliverable

`concept-tutor.html` — a single-file app with:
- A scoping interview baked into the design process (not visible in the final app, but drove every decision)
- A strict-JSON system prompt as the assistant's brain
- A live Claude API integration (no backend, no build step)
- A distinctive "index card on a study desk" UI (not a generic chat box)
- Full loading / error / empty / off-topic states
- An in-app "How this was built" documentation panel

## What I practiced

- **Prompt engineering:** structured output schemas, scope guardrails, vague-input handling, prompt-injection
  resistance
- **Product thinking:** scoping an assistant through incremental, low-effort questions instead of one big brief
- **Frontend design:** deriving a visual identity from the subject matter instead of a template chat UI
- **Documentation-as-product:** treating the "how this was built" explanation as a first-class deliverable
