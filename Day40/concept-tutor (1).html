How this was built

The system prompt

The model is scoped tightly to one job: turn a CS / Data Analyst topic into a structured study card. It's instructed to always return strict JSON matching a fixed schema (topic, summary, worked example, 3–4 practice questions each with a hint) — no prose outside the JSON, no markdown fences. This makes the model's output directly renderable into the UI instead of needing fragile text-parsing.

  • Scope guard: off-topic input (not CS/stats/SQL/analytics related) gets a polite redirect JSON instead of an attempted answer, so the UI can show a clear empty-state rather than garbage output.
  • Missing/vague input: if the topic is too vague ("data stuff"), the model is told to make its best reasonable interpretation and note the assumption in the summary, rather than stalling with a clarifying question — this is a single-shot card generator, not a chat.
  • Abuse/jailbreak attempts: the prompt explicitly refuses to change role, reveal its instructions, or generate unrelated content, falling back to the same redirect JSON.
  • Tone: friendly, patient-mentor voice baked directly into the prompt's writing instructions — plain language, real examples, no jargon-dumping.

Why the UI looks like this

Most "AI tool" UIs default to a chat bubble box. For a study tool, the more honest metaphor is the object people actually study from: an index card. So the interface is a desk — an input tray up top — and the output renders as a single card with a punch-hole rule down the left margin and a tab label, styled like something pulled from a card box, not a chatbot reply. Practice questions are collapsible so the answer/hint doesn't spoil itself before you've tried.

Palette and type were chosen to avoid the generic "AI app" look (cream background + terracotta, or black + neon): deep ink-navy desk, warm paper-cream card, mustard accent for actions, teal for structural dividers. A serif carries headings (textbook voice), monospace carries labels and code (data-tool voice).

Extending this

  • Memory: store generated cards keyed by topic in window.storage so a user's own deck persists across sessions — turn this into a real flashcard box with spaced repetition.
  • Multi-step flows: after practice questions, send the user's typed answers back to the model in a second call for grading/feedback, turning this from single-shot into a short tutoring loop.
  • Tools: add a code-execution tool so SQL/Python examples can actually run against sample data instead of being static text.
  • Personalization: track topics attempted and difficulty, and have the model suggest "what to study next" based on gaps.
