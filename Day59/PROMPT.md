# Day 59 — Reusable Prompt: Launch & Production Readiness (Day 9)

Save this for reuse once the application is actually built and deployed — this prompt assumes both a live URL and a GitHub repo URL exist to review.

---

## The Prompt

Today is Day 9, continuing our chat from the previous days. Before we begin, ask me for my deployed application URL and my GitHub repository URL. If you've forgotten the project or no longer have enough context, ask me to upload the 10-Day Blueprint (Sprint Workbook) before continuing. Use it as the source of truth.

Review everything built so far, then complete only the work scheduled for Day 9 in the Sprint Workbook. Do not redesign the project or begin tomorrow's work.

Before considering the project ready for launch, perform a complete Release Readiness Review — as if launching publicly today. Review and improve: production deployment, environment variables, README/documentation, installation instructions, repo organization, license, project metadata, SEO/social metadata, favicon/branding, error pages, loading states, final UI consistency, performance, accessibility, security, and production configuration. Fix anything preventing a confident public release. Do not introduce new features — focus on polish and completeness.

When complete: do a final end-to-end walkthrough of the deployed app, verify every major workflow, confirm deployed matches local, update the live app and repo if needed, create a meaningful final launch commit, push it, and ask me to test the live app and share screenshots. Finish with a summary of today's work and a brief look at Day 10.

---

## Precondition (learned the hard way, four days running)
This prompt hard-requires a deployed URL and a working local build. If either is missing, don't run this prompt — go back and finish the model finalization + Streamlit app + deployment steps first.
